# پلاسکو منیجینگ — نسخهٔ اندروید (Kotlin)

همان برنامهٔ مغازه، این بار به‌صورت **اپ اندروید بومی** با کاتلین + Jetpack Compose + SQLite.
همه‌چیز آفلاین است: نه سرور، نه اینترنت، نه اجازهٔ اضافه. داده‌ها روی خود گوشی می‌مانند.

## شروع کار

1. **Android Studio** را باز کن → `File → Open` → پوشهٔ `android/` را انتخاب کن.
2. بگذار Gradle خودش را همگام کند (اولین بار چند دقیقه طول می‌کشد و اینترنت لازم دارد).
3. `Run ▶` روی شبیه‌ساز یا گوشی.

ساخت از خط فرمان (روی ویندوز `gradlew.bat`):

```bash
./gradlew testDebugUnitTest   # تست‌های دامنه
./gradlew assembleDebug       # APK آزمایشی
./gradlew assembleRelease     # APK نسخهٔ نهایی (امضاشده)
```

نسخه‌ها در `gradle/libs.versions.toml`: AGP 9.4.1، Kotlin 2.4.21، Compose BOM 2026.09.00،
`compileSdk 37`، `minSdk 26`. از AGP 9 به بعد کاتلین داخل خود AGP است (built-in Kotlin)، پس
پلاگین `org.jetbrains.kotlin.android` عمداً اضافه نشده؛ فقط پلاگین کامپایلر Compose و نسخهٔ
بالاتر KGP روی `buildscript` آمده است.

## چه چیزی ساخته شده

**موتور موجودی (قلب برنامه)** — `data/StockRepo.kt`

- `apply()`، انتقالی دو ساقی با یک `refId`، `undo()` جبرانی، `rebuildLevels()` و انبارگردانی.
- همه در یک تراکنش SQLite؛ موجودی منفی خطا می‌دهد، حرکت با تعداد صفر ثبت نمی‌شود.
- **تنها** نویسندهٔ `stockLevels` همین کلاس است (حتی موجودی اولیهٔ کالای تازه هم از همین راه می‌رود).
- حرکات فقط اضافه می‌شوند؛ اصلاح = حرکت جبرانی با `undoOf`. واگرد یک ساق انتقال، هر دو ساق را برمی‌گرداند.

**داده** — `data/PlascoDb.kt`: جدول‌ها هم‌نام نسخهٔ وب‌اند (`products`، `stockLevels`، `movements`،
`priceChanges`، `stockTakes`، `stockTakeItems`، `brands`، `categories`، `locations`، `settings`)،
با حذف نرم و شناسهٔ UUID. سه مکان پیش‌فرض با **همان شناسه‌های نسخهٔ وب**
(`loc-shop` / `loc-warehouse` / `loc-basement`) و همان پیش‌فرض‌های تنظیمات ساخته می‌شوند، تا بکاپ
دو نسخه روی هم بنشیند.

**بکاپ و بازیابی** — `data/Backup.kt`

- خروجی یک ZIP با `data.json` به شکل `{ schemaVersion, exportedAt, tables }` — همان قالب نسخهٔ وب.
  پس بکاپ گوشی را می‌شود در نسخهٔ وب باز کرد و برعکس (عکس‌ها در این نسخه وجود ندارند).
- دو حالت بازیابی: **جایگزینی** (همه‌چیز پاک، بکاپ می‌نشیند) و **ادغام** (هر ردیف تازه‌تر برنده).
  در هر دو حالت موجودی‌ها از روی حرکات بازسازی می‌شوند و کد کالای تکراری شمارهٔ تازه می‌گیرد.
- اسم و پیشوند دستگاه از بکاپ گرفته نمی‌شود؛ هویت هر گوشی مال خودش است.

**دامنه** — `domain/`: `normalizeFa` (ي→ی، ك→ک، اعراب، نیم‌فاصله، رقم فارسی)، `parseNumberInput`،
نمایش عدد فارسی با «٬» و «٫»، عدد جمع‌وجور (هزار/میلیون/میلیارد)، وضعیت موجودی و `stackLevel`،
`valuate` (ارزش خرید، ارزش فروش، سود بالقوه) و جست‌وجوی AND-محور با رتبه‌بندی.

**تقویم جلالی** — `domain/Jalali.kt`. اندروید تقویم هجری شمسی ندارد، پس تبدیل در خود برنامه است.
الگوریتم با تقویم فارسی ICU برای ۱۴٬۶۰۰ روز پشت‌سرهم (۱۹۵۰–۱۹۹۰) مقایسه شده و صفر اختلاف داشته؛
`domain/JalaliTest.kt` هم همان تاریخ‌ها و رفت‌وبرگشت ده‌ساله را روی **خود کد کاتلین** چک می‌کند.

**صفحه‌ها** — `ui/screens/`

| صفحه | کار |
| --- | --- |
| خانه | عدد درشت (تعداد، قلم کالا، ارزش خرید، ارزش فروش، سود بالقوه)، کم‌موجود/ناموجود، هشدار بکاپ |
| کالاها | جست‌وجوی فارسی، فهرست با پشتهٔ موجودی، فرم کالای جدید/ویرایش، حذف نرم |
| ثبت حرکت | ورود، خروج، تعدیل، خرابی، برگشت‌ها، انتقال؛ ورودی «بسته + عدد» |
| حرکات | فهرست با تاریخ جلالی، واگرد، «بازسازی موجودی‌ها» |
| انبارگردانی | شمارش یک مکان، اعمال با گزارش تعداد تغییر، بازگردانی اعمال |
| بیشتر | تنظیمات (اسم فروشگاه، واحد پول، رنگ، اندازهٔ متن)، برند/دسته/مکان، بکاپ، درباره |

نکتهٔ کوچک تفاوت: فرم «کالای جدید» در این نسخه یک فیلد «موجودی اولیه» هم دارد (در نسخهٔ وب
موجودی اول از راه «ثبت ورود» وارد می‌شود). این فیلد هم فقط از راه موتور حرکات می‌نویسد.

## چه چیزی هنوز نیست (کار بعدی)

- ورود/خروج فایل اکسل، عکس کالا، بارکدخوان دوربین، قفل قیمت خرید.
- فونت وزیرمتن همراه برنامه نیست (فایل فونت در دسترس نبود)؛ از فونت فارسی گوشی استفاده می‌شود.

## نکته‌ها

- تمام رابط راست‌چین است (`LayoutDirection.Rtl`) حتی اگر گوشی انگلیسی باشد.
- رنگ‌ها و اندازه‌ها از `src/styles/tokens.css` نسخهٔ وب آمده‌اند.
- متن‌های فارسی در `ui/Fa.kt` است (یک واژه‌نامه برای هر دو نسخه) نه در `strings.xml`.
- داده‌های هر گوشی جداست؛ برای بردن داده از گوشی به گوشی از «بکاپ» استفاده کن، نه از همگام‌سازی.
- برای اجرا از خط فرمان، `sdk.dir` در `local.properties` باید به پوشهٔ Android SDK اشاره کند.
