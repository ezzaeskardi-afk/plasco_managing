# پلاسکو منیجینگ

اپ مدیریت انبار و فروشگاه محصولات پلاستیکی (خرده و عمده). یک وب‌اپ نصب‌شدنی (PWA) که کاملاً روی دستگاه خودت کار می‌کند: بدون سرور، بدون اینترنت و بدون هزینه‌ی ماهانه.

## چه کاری انجام می‌دهد (فاز ۱)

- **کالاها:** تا هزاران کالا با نام (رنگ و سایز داخل همان نام)، برند، دسته، کد خودکار (`P-00001`)، بارکد، واحد بسته (کارتن + تعداد در بسته)، سه سطح قیمت، حداقل موجودی، عکس و یادداشت — همهٔ فیلدهای پیشرفته زیر «بیشتر» پنهان‌اند.
- **ویرایش سریع قیمت:** از لیست کالاها (آیکن اسکناس هر ردیف) یا صفحهٔ کالا، خرید/خرده/عمده را همان‌جا عوض کن؛ در تاریخچهٔ قیمت ثبت می‌شود و واگرد دارد.
- **جستجوی زیر ۵ ثانیه:** با ارقام فارسی، ی/ي، ک/ك و نیم‌فاصله؛ فیلتر برند/دسته/مکان/وضعیت و ترتیب بر اساس نام، تعداد یا ارزش.
- **موجودی سه‌جا:** مغازه / انبار / زیرزمین (+ قفسه هر کالا در هر مکان) و دفتر حرکات: ورود، خروج، انتقال، تعدیل، خرابی، شمارش. همه با «واگرد».
- **داشبورد:** تعداد کل، تعداد اقلام، ارزش خرید، ارزش فروش، سود بالقوه؛ تفکیک بر اساس مکان/برند/دسته؛ لیست کم‌موجودی و ناموجود.
- **انبارگردانی:** شمارش مکان‌به‌مکان با پیش‌نویس، بازبینی اختلاف‌ها به ترتیب اثر مالی و اعمال یک‌باره.
- **ایمپورت/اکسپورت:** فایل اکسل (`.xlsx`) و CSV شرکت‌ها با نگاشت ستون‌ها، پیش‌بررسی (dry-run) و ثبت دسته‌ای؛ خروجی اکسل و CSV راست‌به‌چپ. حالت **«فقط به‌روزرسانی قیمت»** برای اعمال لیست قیمت شرکت در دو مرحله (کالای ناشناس را نمی‌سازد) و **نگاشت ستون‌ها برای هر فایل یادش می‌ماند** و در ایمپورت بعدی خودکار اعمال می‌شود. هر ثبت ایمپورت یک‌جا **واگرد** می‌شود (کالاهای ساخته‌شده حذف، قیمت‌های قبلی برمی‌گردد) و فهرست ایمپورت‌های اخیر همان‌جاست. اگر موجودیِ بعضی ردیف‌ها بعد از ایمپورت فروخته شده باشد، **واگرد جزئی** انجام می‌شود: همان ردیف‌ها با نام و دلیل گفته می‌شوند و بقیه برمی‌گردند؛ ردیف‌های باقی‌مانده در فهرست می‌مانند (با دکمهٔ «واگرد باقی‌مانده») تا بعداً که موجودی جبران شد هم واگرد شوند.
- **پشتیبان‌گیری:** فایل ZIP شامل کل داده‌ها و عکس‌ها، با بازگردانی دو حالته (جایگزینی کامل یا ادغام) و یادآور هفتگی.
- **قفل قیمت خرید:** با رمز، قیمت خرید و سود برای کارمند پنهان می‌شود (فقط نمایشی).
- **PWA:** نصب روی آیفون/اندروید/ویندوز، کار آفلاین، اعلان به‌روزرسانی، اندازه‌ی متن (۳ سطح) و پوسته‌ی روشن/تاریک. در اولین اجرا از مرورگر «حافظهٔ پایدار» می‌خواهد و وضعیت ماندگاری داده در «بیشتر ← فضای ذخیره‌سازی» معلوم است.
- **وضعیت اپ:** «بیشتر ← وضعیت اپ» در یک نگاه نشان می‌دهد: نسخه و ساختار داده، وضعیت سرویس‌ورکر (کار آفلاین)، اندازه و تعداد فایل‌های کش، سهم فضای ذخیره‌سازی، تاریخ آخرین پشتیبان‌گیری و وضعیت نصب روی دستگاه — و اگر نسخهٔ جدیدی آماده باشد، از همین صفحه «به‌روزرسانی و راه‌اندازی مجدد» را می‌زنی.

## اجرا

```bash
npm install
npm run dev          # سرور توسعه
npm run preview:file # ساخت dist/preview.html: تک‌فایل قابل بازکردن با دوبار کلیک
npm run verify       # typecheck + lint + check:rtl + test + build
npm run dist:check   # چک‌لیست پیش از انتشار: sw.js، مانیفست، هدرها، آیکون‌ها، حجم، تازگی بیلد
npm run dist:zip     # build + چک‌لیست + ساخت plasco-managing-dist.zip آمادهٔ آپلود روی هاست
npm run icons        # ساخت آیکون‌های PWA (بدون کتابخانه‌ی تصویری)
```

> **با دوبار کلیک بازش نکن.** اگر `index.html` را مستقیم از روی سیستم باز کنی، مرورگر اجرای کد اپ روی `file://` را ممنوع می‌کند و صفحه سفید می‌بینی (خودِ صفحه راهنما نشانت می‌دهد). برای نگاه سریع بدون سرور، `npm run preview:file` را بزن و `dist/preview.html` را باز کن؛ نصب و کار آفلاین فقط از روی `npm run preview` (یعنی localhost) یا آدرس https ممکن است.

## انتشار

```bash
npm run dist:zip     # بیلد + چک‌لیست + زیپ آمادهٔ آپلود (plasco-managing-dist.zip)
```

محتوای پوشهٔ `dist/` را روی هر هاست **HTTPS** (دامنه، ساب‌دامین یا زیرپوشه؛ همهٔ مسیرها نسبی‌اند) آپلود کن. دو فایل تنظیمات هدر/نوع فایل (`_headers` برای Netlify/Cloudflare و `.htaccess` برای cPanel) همراه خروجی می‌آید. چون `HashRouter` داریم به قانون rewrite نیازی نیست.

راهنمای کامل — آپلود، HTTPS، نصب روی گوشی و چک آفلاین بعد از انتشار: **[docs/DEPLOY.md](docs/DEPLOY.md)**

خلاصهٔ حیاتی: نصب و آفلاین فقط روی **https** (یا localhost) کار می‌کند؛ روی آیفون فقط **سافاری** می‌تواند نصب کند؛ هر دستگاه دادهٔ خودش را جدا نگه می‌دارد؛ و `sw.js` نباید کش شود.

## پشتیبان‌گیری (مهم)

داده‌ها روی همان دستگاه ذخیره می‌شوند و iOS ذخیره‌سازی را تضمین نمی‌کند؛ پس:

1. هفته‌ای یک‌بار از **بیشتر ← ایمپورت/اکسپورت/پشتیبان ← ساخت فایل پشتیبان** فایل ZIP را بساز و در جای مطمئن (تلگرام/درایو) نگه دار.
2. برای انتقال کارِ انباردار: روی گوشی او هم اپ را نصب کن، او کارش را ثبت کند و در پایان روز فایل پشتیبان بگیرد؛ روی «دستگاه اصلی» با حالت **ادغام** بازگردان.
3. قبل از هر به‌روزرسانی نسخه، پشتیبان بگیر (نسخه‌ی بعدی این کار را خودکار می‌کند).

## راه‌اندازی روز صفر مغازه

1. لیست قیمت شرکت‌ها (اکسل) را با ایمپورت وارد کن؛ در ایمپورت‌های بعدی همین فایل حالت «فقط به‌روزرسانی قیمت» را بزن تا فقط قیمت‌ها عوض شوند. کالاهای بی‌لیست را با «ذخیره و بعدی» دستی بزن.
2. شمارش دو نفره، مکان‌به‌مکان: زیرزمین ← انبار ← مغازه. یکی می‌شمارد، یکی وارد می‌کند.
3. عکس را آخر کار فقط برای کالاهای شبیه‌هم بگیر.
4. بعد از اعمال شمارش هر مکان، ورود و خروج آن مکان فقط از طریق اپ ثبت شود (دو سیستم موازی نگه ندار).
5. هفته‌ی دوم: انبارگردانی نمونه‌ای ۵۰ کالا برای سنجش دقت؛ اختلاف بالای ۲٪ را ریشه‌یابی کن.

## ساختار پروژه

```
src/app          روتر، شل اپ، تنظیمات، گزارش خطا، PWA
src/db           Dexie و اسکیما، مخزن‌ها، حرکات، تاریخچه قیمت، بازسازی موجودی، بکاپ
src/domain       منطق خالص (نرمال‌سازی فارسی، عدد، قالب‌بندی، واحد، ارزش‌گذاری، جستجو، کد)
src/features     dashboard / products / stock / stocktake / importexport / settings
src/components   ui (پایه‌ها) و common (پشته موجودی، ورودی تعداد، ...)
docs/ROADMAP.md  نقشه‌ی فاز ۲ و ۳
docs/DEPLOY.md   راهنمای انتشار، نصب روی گوشی، چک آفلاین
AGENTS.md        قرارداد فنی پروژه (قبل از هر تغییر بخوان)
```
