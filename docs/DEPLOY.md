# راهنمای انتشار، نصب روی گوشی و چک آفلاین

این اپ یک **سایت استاتیک** است: هیچ سرور، دیتابیس یا سرویس بیرونی لازم ندارد. هر هاستی که فایل ثابت بدهد و **HTTPS** داشته باشد کافی است. داده‌ها فقط داخل مرورگر همان گوشی می‌مانند (`IndexedDB`) و پس از نصب، اپ بدون اینترنت کار می‌کند.

> **قبل از هر انتشار: از اپ پشتیبان بگیر** («بیشتر ← ایمپورت/اکسپورت/پشتیبان ← ساخت فایل پشتیبان») و فایل ZIP را جای مطمئن نگه دار.

---

## ۱. آماده‌سازی خروجی

```bash
npm run build      # خروجی در dist/
```

محتوای `dist/` بعد از ساخت این‌هاست:

| فایل | کارش |
|---|---|
| `index.html` | تنها صفحه‌ی اپ (مسیرها با HashRouter است) |
| `assets/` | کد و فونت و CSS؛ نام فایل‌ها هش دارد و جاودانه کش می‌شوند |
| `sw.js` + `workbox-*.js` | سرویس‌ورکر؛ کار آفلاین را همین می‌سازد |
| `manifest.webmanifest` | مانیفست نصب (نام، آیکون، رنگ) |
| `pwa-192.png`, `pwa-512.png`, `pwa-maskable-512.png`, `apple-touch-icon.png`, `favicon.svg` | آیکون‌ها |
| `.htaccess` | تنظیمات Apache/cPanel (نوع فایل‌ها + کش) |
| `_headers` | همان تنظیمات برای Netlify/Cloudflare Pages |
| `robots.txt` | جلوگیری از ایندکس شدن در گوگل |

⚠️ **آنچه آپلود می‌کنی «محتوای» پوشه‌ی `dist/` است، نه خودِ پوشه و نه فایل‌های دیگر پروژه** (`src/`، `node_modules/`، `.env` هیچ‌کدام لازم نیستند و نباید آپلود شوند). نام فایل‌ها را هم عوض نکن.

## ۲. انتخاب هاست

هر کدام از این‌ها کار می‌کند (اپ هیچ درخواست شبکه‌ای در زمان اجرا ندارد):

- **هاست اشتراکی cPanel** (مناسب دسترسی از ایران) — دامنه + SSL رایگان Let's Encrypt از خود پنل.
- **Cloudflare Pages / Netlify / Vercel** — کشیدن پوشه‌ی `dist/` داخل پنل کافی است؛ `_headers` خودکار خوانده می‌شود.
- **GitHub Pages** — چون همه‌ی مسیرها نسبی‌اند (`base: './'`)، انتشار روی زیرمسیر `username.github.io/plasco/` هم بدون تغییر کار می‌کند.

معیارها: پشتیبانی HTTPS، اجازه‌ی بکش‌نکردن `sw.js` (تنظیم هدر)، و اینکه سرور فایل‌های ناشناس را ۴۰۴ ندهد.

## ۳. آپلود

**cPanel (File Manager):**

1. `dist/` را زیپ کن (محتوایش، مثلاً `plasco.zip`).
2. File Manager ← `public_html` (برای ساب‌دامین: پوشه‌ی همان ساب‌دامین).
3. Upload ← Extract. در پایان باید `public_html/index.html` و `public_html/sw.js` را ببینی.
4. زیرپوشه (مثل `public_html/plasco/`) هم بلامانع است؛ آدرس نهایی `https://example.com/plasco/` می‌شود.

**Netlify/Cloudflare Pages:** پوشه‌ی `dist/` را Drag & Drop کن (Build command خالی، Publish directory همان `dist`).

## ۴. تنظیمات سرور (نکته‌ی حیاتی نصب)

دو فایل تنظیمات همراه خروجی می‌آید و روی هاست خودش اعمال می‌شود:

- `.htaccess` برای Apache/cPanel — نوع `webmanifest` و `woff2` را به سرور معرفی می‌کند و برای `index.html`، `sw.js`، `manifest.webmanifest` هدر `Cache-Control: no-cache` می‌گذارد.
- `_headers` برای Netlify/Cloudflare Pages — همان کار.

چرا مهم است؟

- اگر نوع `webmanifest` اشتباه باشد، **مانیفست خوانده نمی‌شود و دکمه‌ی نصب نمی‌آید** (در DevTools علامت «Manifest: syntax error / not found» می‌بینی).
- اگر `sw.js` کش شود، **نسخه‌ی جدید اپ هیچ‌وقت به کاربر نمی‌رسد**.

نکات تکمیلی:

- قانون rewrite لازم **نیست**؛ چون `HashRouter` داریم همه‌ی صفحه‌ها زیر `index.html#/...` هستند.
- روی Cloudflare، برای این دامنه **Rocket Loader و Auto Minify را خاموش کن**؛ فایل `sw.js` را خراب می‌کنند.
- اگر هاست پنل تنظیمات ندارد و می‌خواهی دستی هدر بگذاری: `sw.js` و `index.html` باید `no-cache` و `assets/*` می‌تواند یک‌ساله `immutable` باشد.

## ۵. HTTPS

- در cPanel: بخش SSL/TLS Status ← **Run AutoSSL** (Let's Encrypt)؛ سپس در `.htaccess` یا پنل، ریدایرکت `http → https` را روشن کن.
- HTTPS اجباری است: سرویس‌ورکر، نصب روی گوشی و کار آفلاین فقط در «secure context» ممکن‌اند. آدرس‌های `http://IP` یا `http://192.168.x.x` **نصب و آفلاین ندارند** (فقط برای تست سریع کار می‌کنند).
- `localhost` استثناست و secure حساب می‌شود؛ به همین دلیل تست محلی (بخش ۸) معتبر است.

## ۶. نصب روی گوشی

**اندروید (Chrome):** آدرس https را باز کن → کروم خودش نوار «نصب برنامه» را نشان می‌دهد. اگر نه: منوی ⋮ ← «نصب برنامه». داخل اپ هم «بیشتر ← راهنمای نصب» دکمه‌ی نصب واقعی را می‌آورد.

**آیفون / آیپد:** باید **Safari** باشد (کروم و فایرفاکس روی iOS فقط میان‌بر می‌سازند) → دکمه‌ی اشتراک‌گذاری ← **Add to Home Screen**. از این به بعد اپ بدون نوار آدرس و تمام‌صفحه باز می‌شود.

**ویندوز/مک (Chrome/Edge):** از نوار آدرس، آیکون نصب (⊕ یا «Install») را بزن.

هر دستگاه داده‌ی خودش را جدا نگه می‌دارد؛ برای انتقال بین دستگاه‌ها فقط از فایل پشتیبان استفاده کن.

**حافظهٔ پایدار در اولین اجرا:** اپ در اولین باز شدن، از مرورگر می‌خواهد داده‌ها را «پایدار» نگه دارد (در کروم بی‌صدا انجام میشود). وضعیتش را از داخل اپ ببین: **بیشتر ← فضای ذخیره‌سازی ← ماندگاری داده**؛ اگر «موقت» بود، دکمهٔ درخواست را بزن.

**نکتهٔ مهم آیفون (ماندگاری داده):** اگر سایت را فقط در سافاری باز کنی و ۷ روز سراغش نروی، سافاری حافظه‌ی سایت را پاک می‌کند؛ ولی اپی که به صفحه‌ی اصلی اضافه شده از این قانون **مستثناست** و داده‌اش می‌ماند. با این حال iOS اگر فضای گوشی پر شود (یا خودت «Clear History and Website Data» بزنی) می‌تواند داده‌ها را پاک کند؛ پس روی آیفون پشتیبان هفتگی را جدی بگیر.

## ۶٫۵. تست روی گوشی بدون انتشار (شبکه‌ی محلی)

برای دیدن اپ روی گوشی قبل از آپلود:

```bash
npm run dev -- --host        # یا: npm run build && npx vite preview --host
```

آدرسی مثل `http://192.168.1.5:5173` چاپ می‌شود؛ گوشی را به همان وای‌فای وصل کن و آدرس را باز کن. رابط کامل کار می‌کند و داده هم ذخیره می‌شود، ولی **نصب و کار آفلاین نه** (بدون https سرویس‌ورکر ثبت نمی‌شود). این راه فقط برای تست سریع است؛ نصب واقعی از آدرس https انجام می‌شود.

## ۷. چک آفلاین بعد از انتشار

ترتیب پیشنهادی؛ قدم ۳ اصل ماجراست:

1. **باز کردن اول (با اینترنت):** آدرس https را باز کن، همه‌ی صفحه‌ها (کالاها، انبار، داشبورد، بیشتر) را یک‌بار ببین تا سرویس‌ورکر همه‌ی فایل‌ها را ذخیره کند.
2. **بررسی نصب:** نصب کن، از آیکون صفحه‌ی اصلی باز کن؛ نباید نوار آدرس دیده شود.
3. **تست آفلاین:** اپ را کامل ببند → **WiFi و داده را خاموش کن** (یا حالت هواپیما) → از آیکون باز کن. باید:
   - لیست کالاها و داشبورد بیاید (حتی اگر علامت آفلاین ببینی)؛
   - یک کالای تستی ثبت شود و بعد از بستن و باز کردن آفلاین، همان کالا سر جایش باشد (یعنی نوشتن در IndexedDB سالم است)؛
   - صفحات انبار و «بیشتر» باز شوند.
4. **تست واقعی و پاک‌سازی:** همان کالای تستی را حذف کن، یا موجودی‌اش را با «واگرد» برگردان.
5. **تست اکسل آفلاین:** ایمپورت/اکسپورت اکسل (بخش `exceljs`) هم از پیش کش شده؛ آفلاین یک خروجی بگیر تا مطمئن شوی.
6. **تست به‌روزرسانی:** فایل‌های نسخه‌ی بعدی را آپلود کن → اپ را باز کن → باید نوتیف «نسخه‌ی جدید» بدهد → تأیید کن → نسخه‌ی جدید بیاید (اگر اپ باز بود، یک‌بار ببند و باز کن).

**بررسی فنی روی دسکتاپ (اگر خواستی عمیق‌تر):** DevTools ← Application:

- `Manifest`: نام «پلاسکو منیجینگ»، آیکون‌ها بدون خطای ۴۰۴، و بخش «Installability» سبز.
- `Service Workers`: وضعیت **activated and is running**، Scope همان آدرس اپ.
- `Cache Storage`: یک کش با حدود ۲۰ ورودی (شل اپ + فونت‌ها + آیکون‌ها + چانک اکسل).
- تیک `Offline` را بزن و صفحه را Reload کن؛ باید اپ کامل بالا بیاید.

## ۸. تست محلی قبل از انتشار (اختیاری ولی توصیه‌شده)

```bash
npm run build
npm run preview        # http://localhost:4173 (secure context)
```

همان چک مرحله‌ی ۷ روی localhost هم معتبر است: سرویس‌ورکر ثبت می‌شود، Cache Storage پر می‌شود و با تیک Offline اپ بالا می‌آید.

**نگاه سریع بدون سرور (دوبار کلیک روی فایل):**

```bash
npm run preview:file   # build + ساخت dist/preview.html
```

فایل `dist/preview.html` تمام اپ در یک فایل است و با دوبار کلیک باز می‌شود؛ ولی بدترین راه تست هم هست: **سرویس‌ورکر و نصب ندارد** (file:// نه آدرس https است نه localhost). پس درست‌ترین تست آفلاین همان `npm run preview` است.

## ۹. انتشار نسخه‌های بعدی

1. از اپ پشتیبان بگیر.
2. `npm run build` بزن و **کل محتوای تازه‌ی `dist/` را روی قبلی جایگزین کن** (فایل‌های قدیمی `assets/` را می‌توانی پاک کنی؛ خطرناک نیستند).
3. آدرس تغییر نمی‌کند → همان origin → **داده‌ی نصب‌شده حفظ می‌شود**؛ فقط آیکون اپ یک‌بار با نوتیف به‌روزرسانی می‌آید.
4. اگر مجبور شدی دامنه را عوض کنی (origin جدید)، اپ را دوباره نصب کن و از فایل پشتیبان بازگردانی بزن.

## ۱۰. عیب‌یابی سریع

| علامت | علت احتمالی | راه‌حل |
|---|---|---|
| دکمه‌ی «نصب برنامه» نمی‌آید | http است، یا مانیفست با نوع اشتباه سرو می‌شود | https را چک کن؛ `.htaccess`/`_headers` آپلود شده باشد |
| روی آیفون نصب نمی‌شود | از کروم/فایرفاکس iOS باز شده | فقط Safari ← Add to Home Screen |
| سرویس‌ورکر ثبت نمی‌شود | آدرس IP/بدون https، یا حالت ناشناس | https + پنجره‌ی معمولی |
| آفلاین بالا نمی‌آید | `sw.js` کش شده یا فایل‌های dist کامل آپلود نشده | هدر no-cache را بررسی کن؛ همه‌ی محتوای dist را آپلود کن |
| صفحه‌ی سفید بعد از آپلود | فایل‌ها را جابه‌جا/دستی ویرایش کرده‌ای | محتوای خام `dist/` را از نو آپلود کن |
| پیام «حافظهٔ مرورگر باز نشد» می‌آید | مرورگر IndexedDB را نداد (مرور خصوصی/ناشناس، فضای پر، یا برخی حالت‌های file://) | پنجره‌ی معمولی؛ فضای دیسک آزاد؛ اگر این‌طور نشد از `npm run preview` استفاده کن و داده‌ها را با پشتیبان منتقل کن |
| صفحه‌ی سفید وقتی `index.html` را با دوبار کلیک باز می‌کنم | باز کردن مستقیم از روی سیستم (`file://`): مرورگر اجرای ماژول‌های JS را در این حالت ممنوع می‌کند | از آدرس https/localhost باز کن؛ برای نگاه سریع `npm run preview:file` و بعد `dist/preview.html` |
| بعد از آپلود نسخه‌ی جدید، اپ قدیمی می‌ماند | `sw.js` یا `index.html` کش شده | هدر `no-cache` برای این دو فایل |
| مانیفست خطا می‌دهد | پسوند `webmanifest` شناخته‌شده نیست | `.htaccess` (بخش `mod_mime`) یا تنظیم پنل هاست |
